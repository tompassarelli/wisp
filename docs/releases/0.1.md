# Wisp 0.1
*The engine Mak'gora 0.3 ships on*

**Write a Warcraft III game in TypeScript, test it without the game, and play it either in Warcraft III or in Wisp's own native window.** Wisp is a free fan-made game engine and toolchain: one codebase compiles to the Lua Warcraft runs and also runs natively on your desktop, with rollback netcode for online games. This is the first numbered release, built over the first weeks of development (more than 1,200 commits since 5 October 2026), so until now the commit log was the only history. Smashcraft, and Mak'gora 0.3 on it, is the first game built on Wisp. It is early: tell us what breaks.

## What is in 0.1
- **A native desktop window.** Wisp's own Rust program draws and plays a game with no Warcraft III and no browser running: keyboard, controllers, sound and menus, with the game stepping at 60 a second on its own clock and the picture presented at your display's rate, such as 120 fps. A game starts in it with `wisp play --standalone --window native`.
- **Remastered art, made on your machine.** The window upscales Classic textures on your own GPU with Real-CUGAN (MIT-licensed) and rounds model silhouettes, then lights the result. Pick Original or Remastered at any time on the options screen (F10). The work is cached on your disk and runs in the background, gently during a match.
- **Lighting and effects.** Sun shadows with soft edges, ambient occlusion, contact shadows, bloom, a per-stage colour grade, a procedural sky with clouds, weather, lightning, ribbons and particle emitters. Four graphics presets, Low to Ultra, switch the costly parts off for weaker machines.
- **Water.** Planar reflection, refraction, shore foam and waves for seas, poison and lava, and waterfalls drawn as falling water.
- **A game API of our own.** Twelve families (effects, frames, sound, view, clock, input, sync, players, bodies, events, files and text) that a game calls once. In Warcraft each call is lowered to its native at compile time, so it costs what the native call cost; in the native window the same call runs natively.
- **Rollback netcode and an online relay.** A game supplies its input and a deterministic simulation; Wisp predicts, rolls back and confirms, in Bun and in Warcraft's 32-bit Lua. A UDP relay and a per-player agent give even turn timing instead of Battle.net's, and the native window can host and join a match through it.
- **Maps without World Editor.** Define units and abilities in code, build the terrain and triggers in TypeScript, and pack the map with one command. Types catch mistakes before the map loads, and a Lua error in the game points at your TypeScript line.
- **Hot reload.** Save a file and the running match picks up the code change, with no rebuild and no rehost. New art and object data still need a rebuilt map.
- **Tests without Warcraft.** Simulated clients run your map's real bundle in Bun and in 32-bit Lua, in about a second, and report desyncs, errors and what a player would see wrong. `wisp dev` reruns the affected tests on every save.
- **The farm.** `wisp farm test` runs the full suites for a commit on GitHub's free hosted runners, sharded in parallel, so the development machine never runs them.
- **Capture and diagnosis tools.** Render comparison between renderers, fidelity captures against the real game, a window probe that measures presentation and input latency, frame-cost captures, and repros: a moment of play saved as a test that can be replayed, shrunk and scrubbed.
- **Driving the real game.** One command hosts a match from the desktop, offline LAN matches need no Battle.net account, and a doctor repairs a stuck client.

## How to try it
1. Install Bun, Git and Nix, then run `bun install --frozen-lockfile`.
2. Start from the sample map in `docs/sample-map.md`, which has its build, test, fresh-match and hot-reload commands.
3. Keep `wisp dev` running while you change code.
4. To play in the native window, run your game with `--window native`.

## Requirements
- Linux. The map-packing tools also ship for Windows, and the window builds on Windows in CI, but Wisp is built on and for Linux.
- Your own copy of Warcraft III. The native window loads its art from your install.
- A GPU with Vulkan (Linux) or DX12 (Windows) for the native window.

## Known limits
- The native window is opt-in. Chrome is still the default standalone window until the native one replaces it.
- It does not yet hold 120 fps everywhere. A laptop at a high-resolution 120 Hz panel and the High preset can fall well short and show late frames; Low and Medium are lighter. Smooth play is the main work after this release.
- The first Remastered run bakes textures on your GPU, so the HD art arrives in stages. A few textures still look wrong after upscaling.
- Water has no screen-space reflections, no wave displacement and no splashes at fighters.
- Online play runs through the relay and has been measured on a test pool only. Treat it as an early version.
- Windows and macOS support is tracked but not done: the window runs on Windows in CI with open bugs, and macOS is not built.
- A game linked against an older Wisp steps once per display frame and runs too fast on a 120 Hz panel until it moves to 0.1.

## Fan project and IP statement
Wisp is an independent fan project, not affiliated with or endorsed by Blizzard Entertainment.
- Nothing of Blizzard's (code, art, sound, data, game scripts or in-game text) is in the repository or ships with Wisp. Art loads at run time from your own Warcraft III install.
- Behaviour is measured from the outside: what the game shows, plays, logs and writes, and the traffic of LAN games we host, plus public documentation. Nothing comes from disassembly, decompilation or the game's memory.
- No DRM bypass, no Battle.net emulation, no cheats, and no code from AGPL projects such as Warsmash.
- Remastered textures are made on your machine from your files and cached there; nothing derived from them is written to a repository or a download.
